# تقرير التعديلات والتحقق من التوافق

## 1) تحسين بطء جلب البيانات
تم تنفيذ تعديلات آمنة بدون تغيير منطق العمل:

- رفع مهلة الاتصال في Flutter من 15 ثانية إلى 45 ثانية في `lib/core/network/api_client.dart`.
- إضافة مهلة إرسال `sendTimeout` أيضًا بقيمة 45 ثانية.
- تقليل بطء الـ API الناتج عن فحص بنية قاعدة البيانات في كل طلب، وذلك بإضافة علامة إصدار داخل `app_settings` بعد نجاح التهيئة.
- تقليل تشغيل معالجة الإهلاك الشهرية بحيث لا يتم مسح كل المعدات في كل طلب، بل مرة واحدة لكل شهر.
- إضافة فهارس أداء للجداول الأكثر استخدامًا:
  - `rents(status, start_datetime)`
  - `rents(client_id, status)`
  - `rents(equipment_id, status)`
  - `rents(remaining_amount)`
  - `payments(rent_id, type, is_void)`
  - `payments(created_at, type)`
  - `equipment(is_active, status)`

## 2) مدة الانتظار
تم تغيير مهلة الانتظار في Dio إلى 45 ثانية بدل 15 ثانية.

## 3) ميزة السلسلة عند إضافة معدات
تمت إضافة حقل جديد في نافذة إضافة المعدة:

- `السلسلة / عدد النسخ`

طريقة العمل:

- إذا كتب المستخدم اسم المعدة: `ماطور`
- وكتب في حقل السلسلة: `30`
- ينشئ النظام تلقائيًا:
  - ماطور 1
  - ماطور 2
  - ...
  - ماطور 30

ملاحظات:

- الميزة تعمل فقط عند إضافة معدة جديدة، ولا تظهر عند التعديل.
- باقي بيانات المعدة يتم نسخها كما هي لكل المعدّات الناتجة.
- إذا تم إدخال رقم تسلسلي أساسي، يتم توليد أرقام تسلسلية متسلسلة أيضًا.
- الحد الأعلى الآمن للعملية الواحدة هو 500 معدة.

## 4) توافق Flutter مع API وقاعدة البيانات
تمت مراجعة الحقول الأساسية بين:

- Flutter Equipment model/repository
- `rental_api/equipment.php`
- آخر نسخة قاعدة بيانات SQL داخل مجلد النسخ الاحتياطية

النتيجة:

- حقول المعدات الأساسية متوافقة:
  - `name`
  - `model`
  - `serial_no`
  - `status`
  - `daily_rate`
  - `hourly_rate` للتوافق القديم
  - حقول الإهلاك
  - `is_active`
- حقول العقود الأساسية متوافقة مع API الحالي:
  - `paid_amount`
  - `remaining_amount`
  - `discount_amount`
  - `discount_note`
  - حقول الإغلاق والسداد
- حقول السندات الأساسية متوافقة:
  - `equipment_id`
  - `idempotency_key`
  - حقول الإلغاء
- جدول المتابعات `collection_followups` موجود في قاعدة البيانات ويدعمه الـ API.

## 5) ملاحظات مهمة

- لم يتم حذف أي ملف قديم.
- لم يتم تغيير أسماء الجداول أو الأعمدة القديمة.
- تم الإبقاء على `hourly_rate` للتوافق، لكن النظام يعامله كسعر يومي عند الحاجة.
- التعديلات تمت بطريقة إضافية ومتوافقة حتى لا تكسر البيانات القديمة.
