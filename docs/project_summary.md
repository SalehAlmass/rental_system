# ملخص مشروع نظام التأجير (Rental System App)

بناءً على قراءة ملفات المشروع وهيكل المجلدات، إليك ملخص لأهم المهام والميزات التي يقوم بها المشروع، والتقنيات المستخدمة فيه.

## 1. نظرة عامة (Overview)
المشروع عبارة عن تطبيق للهواتف المحمولة / الويب / سطح المكتب مبني باستخدام إطار عمل **Flutter (Dart)**. يهدف التطبيق إلى إدارة نظام تأجير متكامل (مثل تأجير المعدات أو المركبات أو غيرها)، ويغطي كافة الجوانب التشغيلية والمالية والإدارية.

## 2. الميزات والمهام الأساسية (Core Features)
تم تقسيم النظام بشكل منظم جداً إلى عدة ميزات أساسية (Features) تدل على المهام التي يقوم بها:

* **إدارة عمليات التأجير (Rents)**: المهام الأساسية للتطبيق والتي تتمثل في إنشاء عقود التأجير، متابعة الأصول المؤجرة، وإدارتها. يشتمل النظام على ميزة **الإغلاق التلقائي لعقد التأجير** فور سداد كامل المبلغ المتبقي لتسهيل الدورة التشغيلية والمالية.
* **إدارة المعدات ونظام الإهلاك المحسن (Equipment & Depreciation)**: تسجيل وإدارة المعدات/الأصول المتاحة للإيجار، تتبع حالتها، والكميات المتوفرة. أضيفت ميزة **توليد سلسلة/نسخ متعددة** متسلسلة عند إضافة معدة جديدة (لتسجيل أصول متعددة دفعة واحدة بسلاسة)، بالإضافة إلى نظام متكامل **لتتبع وحساب الإهلاك الشهري والتشغيلي** وقيمتها الدفترية. وفي **المرحلة السادسة (Phase 6.2)**، تم ترقية نظام إهلاك الأصول بالكامل ليصبح وحدة محاسبية متكاملة تدعم الفهرسة والأمان والأتمتة الكاملة. يشمل ذلك تسجيل ومقارنة الأرصدة المالية للأصل (`book_before`/`book_after` و `accum_before`/`accum_after`) قبل وبعد كل فترة، إتاحة واجهة برمجية مفهرسة ومحمية بصلاحيات `GET /depreciation-entries` تعرض سجل حركات الإهلاك، توفير برنامج تشغيل تلقائي ومستقل يعمل عبر سطر الأوامر فقط (`CLI-only Cron`) لإجراء الإهلاك الدوري بأمان، مع بناء واجهة تصفية وعرض متكاملة لسجلات الإهلاك في Flutter ودمج تفاصيل الإهلاك المحسنة في شاشة تفاصيل المعدة.
* **إدارة العملاء (Clients)**: تسجيل بيانات العملاء، ومتابعة سجلاتهم وتعاملاتهم مع النظام.
* **إدارة المدفوعات (Payments)**: تتبع الحركات المالية، تسجيل الدفعات المقبوضة، ومتابعة الأرصدة.
* **نظام الموارد البشرية (HR)**: يتضمن إدارة شؤون الموظفين، ويشمل على سبيل المثال صفحة مخصصة للحضور والانصراف (Attendance).
* **إدارة الورديات (Shifts)**: تنظيم فترات العمل (الورديات) للموظفين داخل النظام. وفي **المرحلة الخامسة**، تم تطبيق الفصل المالي الفردي للوردية لكل مستخدم بشكل كامل. يضمن النظام الآن عدم تداخل الأرصدة النقدية بين الموظفين عبر تتبع المقبوضات (Inflows) والمدفوعات (Outflows) الفردية. يتم احتساب الأرصدة المتوقعة للدرج (Real Drawer Balance) وإجمالي الحوالات البنكية بالخلفية كلياً ولا يُعتمد على البيانات المرسلة من واجهة المستخدم لمنع التلاعب المالي، مع فحص الصلاحيات الإدارية (`shifts_monitoring`) للسماح بمراقبة صناديق الموظفين الآخرين.
* **لوحة التحكم والإحصائيات (Dashboard)**: واجهة رئيسية تقدم نظرة عامة وإحصائيات سريعة حول حالة المعدات، العمليات، والإيرادات.
* **التقارير (Reports)**: إنشاء وعرض تقارير تفصيلية عن أداء العمل والعمليات المختلفة.
* **الطباعة وتصدير البيانات (Print & Export)**: ميزة مهمة لتوليد ملفات PDF وطباعة الفواتير والعقود، وتصدير البيانات (مبنية داخل مجلد core ومجلد print).
* **النسخ الاحتياطي (Backup)**: إمكانية أخذ واسترجاع النسخ الاحتياطية للبيانات من التطبيق والواجهة البرمجية (REST APIs)، بالإضافة إلى نصوص برمجية للتشغيل التلقائي عبر سطر الأوامر (**CLI Backup**). يدعم حفظ النسخ الاحتياطية في مسارات مخصصة، والاحتفاظ بآخر 30 نسخة فقط (Auto-Prune) لتوفير المساحة.
* **المصادقة وإدارة المستخدمين (Auth & Profile)**: تسجيل الدخول للنظام وصلاحيات المستخدمين، حيث يدعم النظام ثلاثة أدوار (مدير/admin، مشرف/manager، موظف/employee) مع صلاحيات مخصصة (permissions_json) تدعم التحكم بالوصول على مستوى الشاشات (screen_permissions) بشكل ديناميكي لكل مستخدم. تم دمج الصلاحيات وتفعيلها بالكامل في المرحلة الثالثة على مستوى واجهات تطبيق Flutter (باستخدام PermissionGuard)، مما يسمح للآدمن بالتحكم في الصلاحيات بشكل مرن ومنفصل لكل مستخدم وتأمين شاشات النظام والواجهات البرمجية (API Endpoints) عبر دالة التحقق المركزي `require_permission`. وفي **المرحلة الرابعة**، تم بناء واجهة إدارة صلاحيات شاشات متكاملة داخل نظام إدارة المستخدمين، مقسمة ديناميكياً إلى مجموعات منسدلة واحترافية (`ExpansionTiles`) ومفاتيح تفعيل حديثة (`SwitchListTiles`) لتسهيل منح وحجب الوصول للمشرفين والموظفين، مع تطبيق حماية أمنية صارمة تمنع الآدمن من حذف نفسه أو تعطيل حسابه أو سلب دوره الخاص (سواء من واجهة Flutter أو من خلال التحقق المركزي بالخلفية API). وتعتمد عملية الحفظ بالخلفية على استراتيجية دمج عميقة وذكية (`Deep Merge`) تضمن تحديث حقول الصلاحيات المخصصة والوصول للشاشات دون حذف أو تعديل أي بيانات جانبية أخرى مخزنة في الحقل (مثل إعدادات الرواتب والحسابات المخصصة للموظف).
* **الإعدادات (Settings)**: التحكم في إعدادات النظام وتخصيصها.
* **سجل التدقيق المالي والعمليات (Financial Audit Trail)**: تم في **المرحلة السادسة (Phase 6.1)** تطوير نظام تدقيق مالي ورقابي متكامل يتتبع كافة العمليات والبيانات الحساسة بالخلفية (مثل تعديل وإلغاء السندات، تحديث بيانات وصلاحيات المستخدمين، وتعديل إعدادات النظام). يقوم النظام بتسجيل القيم القديمة والقيم الجديدة بشكل مقارن (`old_values` و `new_values`) مع حجب تلقائي للبيانات الحساسة (مثل كلمة المرور ورموز المصادقة)، وتوفير واجهة تصفية وبحث متقدمة ومفهرسة للمسؤولين في تطبيق Flutter للرقابة الكاملة والاطلاع على التغييرات.

## 3. البنية البرمجية (Architecture & Structure)
* **Feature-Based Architecture**: يعتمد المشروع على هيكلية تنظيمية ممتازة تقسم التطبيق بناءً على الميزات (في مجلد `lib/features`)، مما يسهل صيانة وتوسيع النظام.
* **Core Folder**: يحتوي على العناصر المشتركة عبر التطبيق مثل:
  * `network`: إعدادات الاتصال بالخوادم والتطبيقات البرمجية (APIs) باستخدام `api_client.dart` مع زيادة مهلة الاتصال لرفع الاستقرار.
  * `storage`: التعامل مع التخزين المحلي وقواعد البيانات المحلية.
  * `printing & export`: أدوات الطباعة وتصدير الملفات.
  * `widgets`: واجهات المستخدم (UI) المشتركة القابلة لإعادة الاستخدام، ومنها حارس الصلاحيات `PermissionGuard` للتحقق ديناميكياً من صلاحيات الشاشات.
* **Theme**: مجلد مخصص لإدارة المظهر العام للتطبيق (الألوان، الخطوط مثل خط Cairo).
* **مستوى قاعدة البيانات والأداء**: تم إدخال فهارس الأداء (Performance Indexes) لتحسين سرعة جلب البيانات من الجداول الأكثر استخداماً (`rents`, `payments`, `audit_logs`, `clients`).

## 4. التقنيات وحزم البرمجيات المستخدمة (Technologies & Packages)
بناءً على ملف `pubspec.yaml` والملفات الأساسية، يعتمد النظام على أحدث التقنيات وأهم الحزم:
* **إدارة الحالة (State Management)**: استخدام `flutter_bloc` لإدارة حالة التطبيق بشكل نظيف وفعال.
* **الاتصال بالشبكة (Networking)**: استخدام حزمة `dio` للتعامل مع الطلبات البرمجية (APIs) بكفاءة عالية، مع زيادة مهلة الاتصال ومهلة الإرسال إلى **45 ثانية** لتحسين أداء النظام مع قواعد البيانات الكبيرة وتفادي انقطاع الاتصال.
* **توليد وطباعة الملفات**: حزم `pdf` و `printing` لإنشاء فواتير وعقود PDF وطباعتها مباشرة.
* **التخزين المحلي**: `shared_preferences` لحفظ الإعدادات وبيانات الجلسات (Tokens).
* **أمان إضافي**: `local_auth` للمصادقة المحلية (مثل البصمة أو الوجه).
* **ميزات إضافية**: 
  * `file_picker`: لاختيار الملفات.
  * `share_plus`: لمشاركة العقود أو التقارير.
  * `url_launcher`: لفتح الروابط أو إجراء مكالمات.
  * `dropdown_search`: لقوائم البحث المنسدلة المتقدمة.

## خلاصة
نظام التأجير هذا هو تطبيق شامل ومبني على أسس برمجية قوية ونظيفة. لا يقتصر على تأجير الأصول فقط، بل يتعداه ليكون نظاماً متكاملاً (ERP مصغر) يشمل إدارة الموارد البشرية، متابعة الورديات، إدارة مالية للمدفوعات، مع دعم كامل لتوليد التقارير وطباعتها.

## المرحلة السابعة (Phase 7): الذكاء المالي وتقارير الإدارة ✅ مكتملة

### الهدف
تحويل نظام التقارير الحالي إلى وحدة تقارير مالية متكاملة (Financial Intelligence Module) توفر رؤية إدارية واضحة وشاملة.

### المنجزات

#### الخلفية (Backend PHP)
- **`helpers_financial.php`** (جديد): مكتبة مشتركة لحساب الأرقام المالية (single source of truth):
  - `calculate_total_revenue()` — إجمالي الإيرادات (غير الملغية)
  - `calculate_rental_revenue()` — إيرادات الإيجار المرتبطة بالعقود
  - `calculate_other_revenue()` — الإيرادات غير المرتبطة بالعقود
  - `calculate_maintenance_expenses()` — مصروفات الصيانة
  - `calculate_operational_expenses()` — المصروفات التشغيلية الخارجة
  - `calculate_payroll_expenses()` — الرواتب المقدرة للفترة (يومية ساعية ومرتب ثابت)
  - `calculate_depreciation_expenses()` — الاستهلاك المحاسبي الشهري
  - `calculate_total_expenses()` — إجمالي كل المصروفات مصنفة
  - `calculate_profit_loss()` — هيكل كامل لقائمة الأرباح والخسائر
  - `calculate_cash_flow()` — التدفقات النقدية مع الرصيد الافتتاحي والختامي
  - `calculate_outstanding_amount()` — إجمالي المستحقات غير المسددة
  - `calculate_total_asset_value()` — القيمة الدفترية الإجمالية للأصول

- **`reports.php`** (محسّن): إضافة 5 واجهات برمجية جديدة محمية بصلاحية `financial_reports`:
  - `GET /reports/financial-summary` — ملخص KPIs + مقارنة بالفترة السابقة
  - `GET /reports/profit-loss` — قائمة الأرباح والخسائر المحاسبية
  - `GET /reports/cash-flow` — تدفقات نقدية (رصيد افتتاحي/حركات/رصيد ختامي)
  - `GET /reports/employee-performance` — أداء الموظفين مالياً
  - `GET /reports/revenue-by-user-summary` — ملخص إيرادات المستخدم (نقد/تحويل)
  - تحسين `GET /reports/equipment-profit` بإضافة: سعر الشراء، أيام الإيجار، عائد الاستثمار ROI

- **`helpers.php`** (محسّن):
  - إضافة صلاحية `financial_reports` لكل الأدوار (admin: true، manager: true، employee: false)
  - إضافة فهارس أداء: `idx_payments_type`، `idx_payments_method`، `idx_payments_is_void`، `idx_rents_status_created`

#### Flutter
- **`pubspec.yaml`**: إضافة حزمة `fl_chart ^0.69.0` للرسوم البيانية
- **`financial_reports.dart`** (جديد): كيانات النطاق لـ FinancialSummary، ProfitLoss، CashFlow، EquipmentProfitRowV2، EmployeePerformanceRow، RevenueByUserSummaryRow
- **`reports_repository_impl.dart`**: إضافة 5 methods جديدة للواجهات البرمجية المالية
- **`reports_event.dart`**: إضافة 6 events: FinancialSummary، ProfitLoss، CashFlow، EmployeePerformance، RevenueByUserSummary، EquipmentProfitV2
- **`reports_state.dart`**: توسيع بـ 18 حقل جديد
- **`reports_bloc.dart`**: معالجات 6 events جديدة
- **`reports_page.dart`** (مُعاد بناؤه بالكامل):
  - 12 تبويب (tabs) مع دعم التصفية بالتاريخ
  - **تب الملخص المالي**: شبكة KPI cards، رسم بياني دائري للمصروفات، تفاصيل الإيرادات
  - **تب الأرباح والخسائر**: هيكل محاسبي P&L مع تلوين ذكي
  - **تب التدفقات النقدية**: رصيد افتتاحي/داخل/خارج/ختامي
  - **تب أرباح المعدات**: بار جارت + تفاصيل ROI لكل معدة
  - **تب أداء الموظفين**: بار جارت + بطاقات الأداء التفصيلية
  - **تب إيرادات المستخدم**: نقد/تحويل/عدد المعاملات
  - **تب الإيرادات**: خط رسم بياني للاتجاه الزمني
  - 5 تبويبات موروثة محسّنة (السندات، أفضل معدات، أفضل عملاء، المتأخرون، الإيرادات بالموظف)

  - `exportFinancialSummary`
  - `exportProfitLoss`

  - `exportEmployeePerformance`

## المرحلة الثامنة - جزء 1 (Phase 8.1): تحسين الحضور والعمل الجماعي للمؤسسات (Enterprise Attendance) ✅ مكتملة

### الهدف
ترقية نظام الحضور والانصراف إلى وحدة إدارة قوى عاملة متكاملة ومحترفة تدعم الاستراحات المتعددة، الفروقات الزمنية للمنطقة، إحصائيات المدير والتحكم بصلاحياته، والمقارنة مع وقت السيرفر الفعلي وتأمين الخروج المالي.

### المنجزات

#### محرك الحسابات الموحد (Unified Calculations Engine)
- **`attendance_calculator.php`** (جديد): مصدر الحقيقة الموحد لحسابات الوقت:
  - `attendance_shift_bounds()` — تحديد أوقات الورديات الرسمية (الصباحية 06:00-12:00، المسائية 16:00-21:00) بدقة.
  - `calculate_attendance_metrics()` — احتساب ساعات العمل الفعلية، التأخير بالدقائق (مع سماحية 15 دقيقة)، الانصراف المبكر، والعمل الإضافي بالدقائق.
  - `compute_seconds_for_logs()` — حساب الثواني الفعلية للعمل والاستراحات من واقع السجلات المتعاقبة زمنياً.
  - `compute_hours_engine()` — حساب ساعات العمل الإجمالية لمدى زمني محدد مع خصم فترات الاستراحة بدقة.

#### الواجهة البرمجية (Backend PHP)
- **`attendance.php`** (محسّن):
  - **تطوير مسار التحضير (Check-In)**: يدعم تسجيل المنطقة الزمنية، نوع ونظام التشغيل للجهاز، وإصدار التطبيق، والتحقق من عدم تكرار تسجيل الدخول وحساب التأخير فورياً.
  - **تطوير مسار المغادرة (Check-Out)**: احتساب وحفظ مقاييس العمل اليومية بالكامل (الاستراحات، التأخير، الانصراف المبكر، العمل الإضافي، ساعات العمل الفعلية)، وتأكيد الخروج الآلي في حال وجود استراحة معلقة.
  - **إضافة مسارات الاستراحات (`attendance/break/start` و `attendance/break/end`)**: لدعم مرونة فترات الاستراحة أثناء الدوام وحفظ تفاصيل الجهاز والوقت الفعلي.
  - **منع تسوية الانصراف المالي (Shift Closing Block)**: فحص وجود مدفوعات مسجلة للموظف اليوم، ومنع تسجيل الانصراف في حال عدم إغلاق الوردية المالية وتسوية العجز أو الفائض النقدي لتفادي التهرب من المسؤولية المالية.
  - **ترقية لوحة تحكم المدير (`GET attendance/admin`)**: دعم تصفية الموظفين حسب الحالة الفورية (يعمل، استراحة، غائب، متأخر)، البحث بالاسم والدور، وجلب إحصائيات الحضور اللحظية لكل الموظفين النشطين.
- **`payroll.php`** و **`helpers_financial.php`** (محسّن):
  - ربط احتساب الرواتب والتقارير المالية بمحرك حساب الحسابات المركزي (`compute_hours_engine`) لضمان عدم تكرار عمليات الاحتساب وتوحيد النواتج في النظام بالكامل.

#### قاعدة البيانات وتحديث الجداول (Database Schema)
- ترقية جدول `attendance_logs` بإضافة الحقول التالية لدعم الميزات الجديدة:
  - `break_minutes`, `late_minutes`, `early_leave_minutes`, `overtime_minutes` (حفظ تفصيلي للمقاييس اليومية).
  - `worked_hours` (الساعات الفعلية المقاسة بعد خصم الاستراحة).

## المرحلة التسعة (Phase 9): تحصين النظام وجاهزية التشغيل المؤسسي (Production Hardening & Session Security) ✅ مكتملة

### الهدف
ترقية البنية التحتية للنظام وأمان الجلسات إلى درجة عالية من الموثوقية والأمان المؤسسي (Production-Grade)، بما يشمل تشفير الرموز الأمنية، حماية مسارات ومجلدات النظام، الكشف الذاتي عن تعارضات البيانات، وسجل تدقيق شامل للعمليات الأمنية الحساسة.

### المنجزات

#### 1. أمان الجلسات والرموز الأمنية (Token & Session Security)
- **عزل وتتبع الجلسات النشطة**: إنشاء جدول `user_sessions` لتسجيل كل جلسة تسجيل دخول نشطة مع حفظ تفاصيل الجهاز (Device Name, Platform)، تاريخ آخر نشاط، ووقت انتهاء الصلاحية.
- **تجزئة الرموز الأمنية**: تخزين بصمة الرمز الأمني باستخدام خوارزمية التجزئة الآمنة SHA-256 لحماية قاعدة البيانات في حال تسريب البيانات.
- **إدارة الجلسات الحية**: توفير واجهات برمجية لـ:
  - تسجيل الخروج الفعلي (`POST auth/logout`) لإبطال صلاحية الجلسة فورياً.
  - جلب الجلسات الفعالة للمستعمل (`GET auth/sessions`) لتمكينه من مراقبة أجهزته.
  - إنهاء جلسة معينة (`DELETE auth/sessions/{id}`) لإلغاء الوصول لجهاز بعيد.
  - سحب الصلاحيات الإداري وقسر الخروج (`POST admin/sessions/revoke-user`) لتمكين المشرفين من تسجيل خروج فوري لأي موظف معطل أو مشبوه.
- **توافق الجلسات القديمة (Migration Compatibility)**: توفير آلية مرنة تسمح بالانتقال التدريجي دون إجبار المستخدمين الحاليين على تسجيل الخروج الفوري، مع إتاحة خيار فرض التحقق الصارم بمجرد اكتمال الهجرة.

#### 2. تشفير وأمان كلمات المرور (Password Hardening)
- **التشفير المحسن بكفاءة**: تعديل واجهات إنشاء وتحديث المستخدمين لحفظ كلمات المرور باستخدام التجزئة المحسنة `password_hash()` مع خوارزمية (BCrypt) بدلاً من النص الصريح.
- **الترقية التلقائية الصامتة (Auto-Upgrader)**: دمج آلية ذكية تفحص كلمة المرور أثناء تسجيل الدخول؛ وفي حال تطابقها مع النص القديم، تشفرها فورياً وتحدثها في قاعدة البيانات دون مقاطعة تجربة الموظف.

#### 3. أتمتة وتأمين النسخ الاحتياطي (Backup Hardening & Cron)
- **حماية المجلدات والوجهات**: وضع قيود أمنية صارمة تمنع حفظ أو نسخ الملفات إلى مجلدات النظام الحساسة (مثل `C:/Windows`, `/etc`) أو استبدال ملفات الكود المصدري للتطبيق، مع السماح فقط بالمجلدات المعتمدة والآمنة.
- **سجل عمليات النسخ**: إنشاء جدول `backup_logs` لتوثيق جميع محاولات النسخ والنجاح والفشل، مع تسجيل الحركات محاسبياً في سجل التدقيق المالي.
- **جدول النسخ الآلي (Cron Backup)**: برمجة نص تشغيل ذاتي (`cron/database_backup.php`) يعمل يومياً بالخلفية وينفذ سياسة الاحتفاظ بـ:
  - النسخ اليومية لآخر 30 يوماً.
  - النسخ الشهرية (الأول من كل شهر) لآخر 12 شهراً، وتطهير ما سواها آلياً لتوفير مساحة القرص.

#### 4. لوحة مراقبة سلامة وصيانة النظام (System Health & Integrity Dashboard)
- **الواجهة البرمجية للصيانة (`GET /system-health`)**: واجهة إدارية شاملة ترصد حالة اتصال قاعدة البيانات، إجمالي حجم الجداول (MB)، إصدار PHP والملحقات المفعلة (Extensions)، المساحة الحرة للقرص المتاح (GB)، زمن الاستجابة الفعلي للـ API بالملي ثانية، وعدد الجلسات الحية.
- **فحص تعارض وسلامة البيانات (`GET /system-integrity`)**: مسح آلي دقيق يكشف:
  - عقوداً بلا عملاء أو بلا بنود معدات.
  - سندات قبض أو صرف بلا عقود مرتبطة أو بقيمة سالبة/صفرية.
  - معدات بحالات تشغيلية غير معرفة أو بقيمة إهلاك متراكم تتجاوز قيمة الشراء.
  - موظفين في حالة تحضير مستمر دون انصراف لأكثر من 24 ساعة، أو بتسجيلات حضور مكررة في نفس اليوم.
- **واجهة المشرفين في Flutter (`SystemHealthPage`)**: شاشة عصرية تفاعلية تعرض بطاقات الحالة الفورية، مسحاً حياً لتنبيهات سلامة البيانات، وسجل تتبع تفصيلي لآخر 50 خطأ برمجي مسجل بالخادم مع القدرة على قراءة Stack Trace الفني لتسريع الصيانة.

#### 5. توسيع سجل التدقيق الأمني (Security Audit Trails)
- تتبع وتسجيل الأحداث الأمنية الهامة: `login_success`, `login_failed`, `logout`, `session_created`, `session_revoked`, `admin_force_logout`, `password_changed`.
- تسجيل تفاصيل العميل بالكامل بما يشمل عنوان الـ IP ووصف جهاز العميل (User-Agent).

## Database Migration System (Phase 10.5)

### الوصف
نظام آمن لإدارة تحديثات قواعد بيانات العملاء (Client Databases) عند تثبيت نسخة جديدة من النظام. يقوم بمقارنة schema الحالي مع schema المرجعي، وتنفيذ التحديثات الآمنة فقط مع backup تلقائي قبل أي تغيير.

### المكونات

| الملف | المسار | الوظيفة |
|-------|--------|---------|
| `migration_manager.php` | `rental_api/migrations/` | الصنف الأساسي - يقارن، يخطط، ينفذ، يسجل |
| `cli_migrate.php` | `rental_api/` | واجهة سطر الأوامر (CLI) |
| `migrations.php` | `rental_api/` | واجهة API (GET status, POST run) |
| `reference_schema.sql` | `rental_api/migrations/` | الـ schema المرجعي (dump بدون بيانات) |

### جدول التتبع

`system_migrations` - يسجل كل عملية تحديث:
- `version`: بصمة زمنية (Ymd_His)
- `checksum`: MD5 للخطة
- `status`: pending / running / completed / failed
- `backup_file`: مسار النسخة الاحتياطية
- `details`: JSON يسجل كل خطوة (applied/skipped مع error)
- `execution_time_ms`: زمن التنفيذ

### العمليات المسموحة

| العملية | مسموح؟ |
|---------|--------|
| CREATE TABLE IF NOT EXISTS | ✅ |
| ALTER TABLE ADD COLUMN IF NOT EXISTS | ✅ |
| CREATE INDEX IF NOT EXISTS | ✅ |
| ALTER TABLE ADD FOREIGN KEY | ✅ |
| DROP TABLE / DROP COLUMN | ❌ |
| DELETE / TRUNCATE | ❌ |

### آلية العمل

```
CLI: php cli_migrate.php
  → 1. إنشاء backup (mysqldump)
  → 2. قراءة reference_schema.sql
  → 3. مقارنة الجداول / الأعمدة / الفهارس
  → 4. إنشاء خطة التحديث
  → 5. تنفيذ الخطة (مع تخطي الأخطاء)
  → 6. تسجيل في system_migrations
  → 7. إنشاء تقرير migration_report.md
```
